## The same adapter idea, a different forward pass

<Term id="lora">LoRA</Term> (Low-Rank Adaptation) injects small trainable matrices into a **frozen** base so you specialise a huge model without rewriting it (Hu, Shen, Wallis, Allen-Zhu, Li, Wang, Wang, & Chen, 2022, arXiv:2106.09685). Unsloth's wording for LLMs is the one you already met: freeze the base in 16-bit (or 4-bit for QLoRA), train thin A and B on linear layers, on the order of **1% of the weights** ([Unsloth fine-tuning guide](https://unsloth.ai/docs/get-started/fine-tuning-llms-guide)).

Comfy-Org's LoRA page says the same algebra for generative image models: introduce trainable low-rank matrices, adjust only a portion of parameters, lower cost than retraining the whole checkpoint. Compared to a base such as SD1.5, LoRA files are **smaller and easier to train**. All LoRA variants they list — Lycoris, loha, lokr, locon, etc. — **are used the same way** in ComfyUI ([Comfy-Org, ComfyUI LoRA example](https://docs.comfy.org/tutorials/basic/lora)).

The file lives in `ComfyUI/models/loras`. The node is **Load LoRA**, and it sits **between** Load Checkpoint and KSampler. That is the whole topology of this lesson.

## Official Load LoRA sockets

Comfy-Org's table, copied not paraphrased into fiction ([LoRA example](https://docs.comfy.org/tutorials/basic/lora)):

**Inputs**

| Parameter | Function |
| --- | --- |
| `model` | Connect to the base model |
| `clip` | Connect to the CLIP model |
| `lora_name` | Select the LoRA file ComfyUI detected under `models/loras` |
| `strength_model` | How strongly the LoRA influences **model weights**; higher = stronger style |
| `strength_clip` | How strongly the LoRA influences **CLIP text embeddings** |

**Outputs**

| Parameter | Function |
| --- | --- |
| `model` | Base with LoRA adjustments applied |
| `clip` | CLIP with LoRA adjustments applied |

Those two strengths are **not** one knob. A LoRA can move the UNet/DiT more than the text encoder, or the other way around. If the trigger word is in the prompt but the look does not land, try raising `strength_model` first; if the prompt itself starts to drift into the LoRA's dialect, you are looking at `strength_clip`. That heuristic is an operator reading of Comfy-Org's two-row table, not a paper result — tune on a locked seed from the previous lesson (CivitAI article 22492 seed FAQ).

The node **chains**. Multiple Load LoRA nodes in series apply multiple adapters. Comfy-Org points at [Multiple LoRAs](https://docs.comfy.org/tutorials/basic/multiple-loras) for the layout. Order is a creative choice they do not reduce to a formula on the basic page.

## CivitAI card: version, base, trigger, license

The catalog is [civitai.com/models](https://civitai.com/models). Comfy-Org's own example downloads **from CivitAI** (dreamshaper 8, blindbox_V1Mix). A card is not a vibe. Read, in this order:

1. **File format.** Prefer **safetensors**. Pickle `.ckpt` is a program (Python Software Foundation, pickle; [Hugging Face safetensors](https://huggingface.co/docs/safetensors/index); previous lesson).
2. **Version** (`modelVersionId`). Comfy-Org's download URLs pin 128713 and 32988. A "same model" on CivitAI can ship a 1.5 version and an XL version as **siblings**. Download the version whose **base model** field matches the checkpoint already in Load Checkpoint.
3. **Base model compatibility.** An **SD1.5 LoRA on an SDXL checkpoint is the wrong family**. Different latent size, different CLIP stack (Podell et al., 2023, arXiv:2307.01952 versus Rombach et al., 2022, arXiv:2112.10752). The graph will still **run**. The image often looks like **noise**, texture soup, or a smeared checkpoint. That is this lesson's case.
4. **Trigger words.** Many concept/character LoRAs only fire when a rare token from the card is in the **positive** CLIP encode. If the card says the trigger is `ohwx person` and you never type it, `strength_model = 1` will not invent the concept. The card is the source; this course will not invent a trigger for a LoRA you did not open.
5. **License / creator terms.** CivitAI cards and Hugging Face cards both carry terms. Unsloth does not waive them when the algebra is the same. Read the version you downloaded ([CivitAI models](https://civitai.com/models); [Comfy-Org Models](https://docs.comfy.org/basic-concepts/models) on community fine-tunes).

## When it looks like noise: the mismatch case

**Case.** You download a LoRA whose thumbnail is gorgeous, drop it on your working SDXL (or Flux) checkpoint, Queue, and get **coloured noise** or a melted face. The card's **base model** field said SD 1.5 (or "SD 1.5 merged"). Load LoRA does not type-check families. It adds low-rank deltas into whatever `model` / `clip` you wired. Wrong shape / wrong CLIP ⇒ the denoise trajectory leaves the manifold the VAE knows how to decode (Rombach et al., 2022; Podell et al., 2023). Fix: match families, or run the LoRA on the base the card names (often an SD1.5 such as dreamshaper_8, as in Comfy-Org's example). Do not raise `steps` to 80 as a first debug — that is the previous lesson's blurry-image knob, the wrong axis.

A second failure mode: right family, **forgotten trigger**. The LoRA was trained so that a token occupies a direction in CLIP space (Radford et al., 2021, arXiv:2103.00020). Without the token, you are applying a small random-looking delta. Read the card.

A third: `strength_model` at 2.0 on a LoRA whose card says 0.6–0.8. Comfy-Org tells you higher is stronger; it does not tell you to double it. Over-strength is fried texture, not "more style."

<Myth>
"A LoRA is a full checkpoint, so it replaces Load Checkpoint." No. Hu et al. (2022) and Comfy-Org both describe an **adapter on a frozen base**. You still need Load Checkpoint. Load LoRA **in between**. A "LoRA" file dropped into `models/checkpoints` will not appear in Load Checkpoint (wrong subfolder — [Models](https://docs.comfy.org/basic-concepts/models)). A checkpoint dropped into `models/loras` will not appear in Load LoRA.
</Myth>

## ControlNet is the next helper, not this class

Comfy-Org's models page lists **ControlNet** next to LoRA: extra guidance from edges, depth, pose; files under `ComfyUI/models/controlnet/` ([Models](https://docs.comfy.org/basic-concepts/models)). CivitAI article 22492 names ControlNet as a next step after the first workflow ([article 22492](https://civitai.com/articles/22492/comfyui-tutorial-2-building-your-first-workflow)). This lesson stops at **mention**: ControlNet is a second network that conditions the denoise on an auxiliary image (pose stick figure, depth map). It is not a LoRA. It does not go in `models/loras`. It does not use `strength_clip`. Learn it on a graph that already produces a clean image with a matched LoRA.

## Chaining, without a new myth

Comfy-Org: Load LoRA **supports chain connections**; see the multiple-LoRAs tutorial ([LoRA example](https://docs.comfy.org/tutorials/basic/lora); [Multiple LoRAs](https://docs.comfy.org/tutorials/basic/multiple-loras)). Operator rules you can defend from that topology:

- Every extra Load LoRA must still see a `model` and `clip` that already match the **same** base family.

## Why two strengths exist (CLIP versus UNet)

CLIP is a **text** encoder (Radford et al., 2021). The denoiser is a **UNet or DiT** (Rombach et al., 2022; later families). Hu et al. (2022) attach LoRA to linear layers wherever you choose. A diffusion LoRA often ships deltas for **both** the denoiser and CLIP. Comfy-Org therefore exposes `strength_model` and `strength_clip` as separate inputs ([LoRA example](https://docs.comfy.org/tutorials/basic/lora)). Turning only `strength_model` changes how the artist paints; turning `strength_clip` changes how the artist **hears** the prompt. If a trigger is a CLIP-space token, `strength_clip = 0` can mute it even when the word is in the box.

That is the academic reason the node is not a single slider.

## Case — the strength slider at 2.0 over a LoRA trained for 0.7

An illustration studio publishes weekly thumbnails with their own LoRA. They switch base to SDXL but keep a LoRA trained on SD 1.5 with `recommended strength 0.6–0.8` on the card. An editor cranks `strength_model = 2.0` expecting "more of the style." Outputs come back fried: cracked textures, sunken eyes, occasional colour banding where hair should be. Not a model bug, it is the low-rank delta multiplied by a scalar outside the range the adapter was trained for. They drop to 0.7, set `strength_clip` to 0.7 too, and the style returns to the territory the LoRA actually knows how to produce. Operational lesson: the strength slider is not "how much I want." It is "how much this adapter can take." The CivitAI card names the range; if it does not, start at 0.6 and step by 0.1, not by 0.5.
