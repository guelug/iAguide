## One turn, five verbs

Every serious harness — Hermes Agent, OpenClaw, a chat-box you wrote on a Saturday — does the same dance:

1. **Intake** a user message (and maybe a queued interrupt).
2. **Assemble** context: system policy, skills, memory snapshots, recent turns.
3. **Call the model** (chat completions, native Messages, Responses, or an embedded runtime).
4. **Run tools** if the model asked for them; loop until text or budget.
5. **Persist** the transcript and flush durable memory.

The model is replaceable. The loop is the product.

## Interrupt, budget, fallback (general ideas)

- **Interruptible** — an HTTP call or tool batch can be abandoned when the user sends `/stop` or a new message. Partial assistant text must not pollute the transcript.
- **Budget** — a hard iteration or wall-clock ceiling so a runaway tool loop cannot burn a weekend of tokens.
- **Fallback** — when the primary provider returns 429/5xx/auth failure, try a configured chain. Subagents often do **not** inherit that chain (isolation beats cleverness).

## Hermes vs OpenClaw (light)

Hermes puts the loop in one `AIAgent` class (`run_agent.py`) shared by CLI, gateway, ACP, cron, and library callers. OpenClaw owns a **Gateway** process: `agent` RPC accepts immediately, then an embedded run streams `assistant` / `tool` / `lifecycle` events and waits via `agent.wait`. Same verbs; different ownership of the process.

## Case: the interrupted half-reply

**Case.** A Telegram user hits send while the model is mid-stream. The harness injects the new text as a steer/interrupt but also appends the truncated assistant fragment as a finished turn. Next call: two assistant messages in a row → provider 400.

**Fix pattern.** On interrupt: abandon the API thread, do not commit partial assistant content, queue or steer the new user text, then continue with valid alternation.
