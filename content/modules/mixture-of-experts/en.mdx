## Most parameters can sleep

A dense layer uses every weight on every token. A **mixture of experts** routes each token to a few expert MLPs. Total parameter count can be huge; **active** parameters per token stay smaller. That is why a “400B MoE” can run closer to a 30B dense in FLOPs — and still need enough VRAM to *hold* the experts you are not firing.

Routing must stay balanced or a few experts overfit and others die. Model cards will say active params, number of experts, and top-k. Believe the card; measure memory yourself.

## Case — MoE-on-Mac optimism

A team bought a Mac because “active params are 17B.” The quant still mapped all experts into unified memory and the machine swapped. Active FLOPs were fine. Resident weights were not.
