## The waist is a process

OpenClaw's [*Gateway architecture*](https://docs.openclaw.ai/concepts/architecture) (n.d.) is the primary source. A single long-lived **Gateway** owns all messaging surfaces: WhatsApp via Baileys, Telegram via grammY, Slack, Discord, Signal, iMessage, WebChat. Control-plane clients (macOS app, CLI, web UI, automations) connect to the Gateway over **WebSocket** on the configured bind host, default `127.0.0.1:18789`.

**Nodes** (macOS, iOS, Android, headless) also connect over WebSocket, but declare `role` equal to `node` with explicit caps and commands (OpenClaw, *Gateway architecture*, n.d.).

One Gateway per host. It is the only place that opens a WhatsApp session. That sentence is the particularity. Two processes that both open Baileys against the same session are not a cluster; they are a conflict.

The hosted widget surface is served by the Gateway HTTP server on the same port (default 18789):

- `/__openclaw__/canvas/` — hosted widget documents
- `/__openclaw__/a2ui/` — A2UI renderer assets

The generic [gateway](/en/m/gateway) lesson stays harness-agnostic. This one is the OpenClaw daemon.

## Components and flows

The Gateway daemon maintains provider connections, exposes a typed WS API (requests, responses, server-push events), validates inbound frames against JSON Schema, and emits events such as `agent`, `chat`, `presence`, `health`, `heartbeat`, and `cron` (OpenClaw, *Gateway architecture*, n.d.).

Clients (mac app, CLI, web admin) hold one WS connection per client. They send requests (`health`, `status`, `send`, `agent`, `system-presence`) and subscribe to events (`tick`, `agent`, `presence`, `shutdown`).

Nodes connect to the **same WS server** with `role` `node`. They provide a device identity in `connect`. Pairing is **device-based** (role `node`) and approval lives in the device pairing store. They expose commands such as `camera.*`, `screen.record`, and `location.get`. The macOS app also exposes widget-panel commands under `canvas.*`. Protocol details live on *Gateway protocol* (OpenClaw, n.d., https://docs.openclaw.ai/gateway/protocol).

WebChat is a static UI that uses the Gateway WS API for chat history and sends. In remote setups it connects through the same SSH or Tailscale tunnel as other clients.

<Callout>
Exactly one Gateway controls a single Baileys session per host. Handshake is mandatory; any non-JSON or non-connect first frame is a hard close. Events are not replayed; clients must refresh on gaps (OpenClaw, *Gateway architecture*, n.d.).
</Callout>

## Connection lifecycle

OpenClaw's architecture page draws a single-client sequence (n.d.):

```text
Client -> Gateway: req connect
Gateway -> Client: res ok
  or res error plus close
  payload hello-ok
  snapshot: presence plus health

Gateway -> Client: event presence
Gateway -> Client: event tick

Client -> Gateway: req agent
Gateway -> Client: res agent ack (runId, status accepted)
Gateway -> Client: event agent (streaming)
Gateway -> Client: res agent final (runId, status, summary)
```

The first frame **must** be `connect`. After handshake, requests carry type `req` with id, method, params; responses carry type `res` with id, ok, and payload or error; events carry type `event` with event name, payload, optional seq and stateVersion. Put those shapes in a client from *Gateway protocol*, not from memory of this lesson (OpenClaw, *Gateway protocol*, n.d.).

`hello-ok.features.methods` and `events` are discovery metadata, not a generated dump of every callable helper route (OpenClaw, *Gateway architecture*, n.d.; *Gateway protocol*, n.d.).

Shared-secret auth uses `connect.params.auth.token` or `connect.params.auth.password`, depending on the configured gateway auth mode. Identity-bearing modes such as Tailscale Serve (`gateway.auth.allowTailscale` true) or non-loopback `gateway.auth.mode` `trusted-proxy` satisfy auth from request headers instead of `connect.params.auth`. Private-ingress `gateway.auth.mode` `none` disables shared-secret auth entirely; keep that mode off public or untrusted ingress.

Idempotency keys are required for side-effecting methods (`send`, `agent`) to safely retry. The server keeps a short-lived dedupe cache. Nodes must include `role` `node` plus caps, commands, and permissions in `connect`.

## Pairing and local trust

All WS clients (operators and nodes) include a **device identity** on `connect`. New device IDs require pairing approval. The Gateway issues a **device token** for subsequent connects (OpenClaw, *Gateway architecture*, n.d.).

Direct local loopback connects can be auto-approved to keep same-host UX smooth. OpenClaw also has a narrow backend or container-local self-connect path for trusted shared-secret helper flows. Tailnet and LAN connects, including same-host tailnet binds, still require explicit pairing approval.

All connects must sign the `connect.challenge` nonce. Signature payload `v3` also binds `platform` and `deviceFamily`. The gateway pins paired metadata on reconnect and requires repair pairing for metadata changes. **Non-local** connects still require explicit approval. Gateway auth (`gateway.auth.*`) still applies to **all** connections, local or remote.

Details: *Gateway protocol*, *Pairing*, *Security* (OpenClaw, n.d.).

TypeBox schemas define the protocol. JSON Schema is generated from those schemas. Swift models are generated from the JSON Schema.

## Remote access

Preferred remote path: Tailscale or VPN (OpenClaw, Gateway architecture, n.d.). Alternative: SSH local-forward of port 18789 to loopback on the gateway host. The architecture page prints that one-liner.
The same handshake and auth token apply over the tunnel. TLS plus optional pinning can be enabled for WS in remote setups.


## Operations snapshot

Start: `openclaw gateway` (foreground, logs to stdout). Health: `health` over WS (also included in `hello-ok`). Supervision: launchd or systemd for auto-restart (OpenClaw, *Gateway architecture*, n.d.).

That is the operator contract. A laptop that only runs `openclaw acp` is not the Gateway. ACP bridge talks **to** a running Gateway (OpenClaw, *ACP*, n.d., https://docs.openclaw.ai/cli/acp).

## Roles on the same socket

The protocol is one WebSocket server with roles declared at handshake (OpenClaw, *Gateway protocol*, n.d.). `operator` is a control-plane client (CLI, UI, automation). `node` is a capability host (camera, screen, canvas, system.run). `worker` is a cloud execution host on a dedicated closed worker protocol, not the general operator RPC surface.

Nodes declare caps, commands, and permissions as **claims**. The Gateway enforces server-side allowlists. Do not treat a connect-time cap as authorization.

Current clients and servers run protocol v4. Clients send `minProtocol` plus `maxProtocol`. Node clients may use the N-1 node protocol (currently v3) when both role and client.mode are node (OpenClaw, *Gateway protocol*, n.d.).

Pre-connect frames are capped at 64 KiB. After handshake, follow `hello-ok.policy.maxPayload` and `hello-ok.policy.maxBufferedBytes`. Default advertised maxPayload in the protocol example is 26214400 bytes. Tick interval in that example is 15000 ms. Honor the hello-ok policy rather than hardcoding (OpenClaw, *Gateway protocol*, n.d.).

## hello-ok is a snapshot, not a live config

`hello-ok` carries protocol, server version and connId, feature discovery, a snapshot, auth (role and effective scopes), and policy. `deviceToken`, when present, is the primary reusable credential for the same device and role (OpenClaw, *Gateway protocol*, n.d.).

Attachment ceilings in `policy.attachments` are optional on older gateways. `maxBytes` is the largest decoded size for a single attachment (`agents.defaults.mediaMaxMb`, default 20 MB). `maxImageBytes` is min of that and a 6 MB agent-hydration cap. Re-read those values on every reconnect. They are a connection-time snapshot.

`hello-ok.features.methods` is a conservative discovery list. Some real methods are intentionally excluded from discovery (the protocol page names `push.test`, `web.login.start`, `web.login.wait`, `sessions.usage`). Treat discovery as feature detection, not a full dump of server-methods (OpenClaw, *Gateway protocol*, n.d.).

While startup sidecars are still finishing, `connect` can return a retryable `UNAVAILABLE` with details.reason `startup-sidecars` and `retryAfterMs`. Retry within the connection budget instead of treating it as a terminal handshake failure.

Hosted widgets stay on the Gateway HTTP server under `/__openclaw__/canvas/` and `/__openclaw__/a2ui/`. `pluginSurfaceUrls` in hello-ok may expire; nodes refresh with `node.pluginSurface.refresh`. The deprecated canvasHostUrl path is not supported (OpenClaw, *Gateway protocol*, n.d.).

Broadcast events are scope-gated. Chat, agent, and tool-result frames require at least `operator.read`. Status and transport events (`heartbeat`, `presence`, `tick`, connect/disconnect lifecycle) stay unrestricted so transport health is observable to every authenticated session. Unknown broadcast families are fail-closed unless a registered handler relaxes them (OpenClaw, *Gateway protocol*, n.d.).

Each client connection keeps its own per-client sequence number. Events are still not replayed across a reconnect. A gap means refresh, not a replay buffer you invent (OpenClaw, *Gateway architecture*, n.d.).

Idempotency keys are required for side-effecting methods such as `send` and `agent`. The server keeps a short-lived dedupe cache. Teaching retry-without-key as safe is how a double send lands in Telegram twice.

Cite OpenClaw, *Gateway architecture*, n.d., as the parent of the process model: one daemon, port 18789, clients plus nodes, one Baileys owner. Cite *Gateway protocol* for every frame field. Cite Nous Research, *Gateway Internals*, n.d., only in the compare paragraph.

This lesson stops at the daemon, the bind, pairing trust, the three invariants, and the SSH or Tailscale remote. Cron RPCs, session keys, and browser loopback live in later OpenClaw lessons. Do not dump the entire method catalog here. The protocol page already warns that hello-ok methods are not that catalog.

Read *Pairing* when a new device id is rejected. Read *Security* when `gateway.auth.mode` is `none` on a public bind. Read *Queue* when `agent` acks accepted but work waits. Read Hermes *Gateway Internals* only when the product is Hermes.

WebChat uses the same WS API for history and sends. In remote setups it shares the SSH or Tailscale tunnel with other clients (OpenClaw, Gateway architecture, n.d.).

One WS connection per control-plane client. Nodes are not a second server; they are a role on this server.

The macOS app exposes widget-panel commands under canvas.* in addition to camera, screen, and location node commands (OpenClaw, Gateway architecture, n.d.).

Start in the foreground first. Add launchd or systemd only after hello-ok is healthy (OpenClaw, Gateway architecture, n.d.).

## Case — the gateway that restarted itself

A team watched the gateway fall every few hours. The log showed a crash-loop from an adapter that did not close the connection. The waist is a process: if an adapter does not respect the connection lifecycle, the whole process pays the price.
