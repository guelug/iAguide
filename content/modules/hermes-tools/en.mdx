## Registry as a rack

Each tools/*.py calls registry.register(...) at import. discover_builtin_tools AST-scans for top-level register() then imports (skips registry.py, mcp_tool.py). Then MCP discover + plugin tools.

Shadowing across toolsets is rejected unless override=True; plugins also need plugins.entries.<id>.allow_tool_override.

get_tool_definitions filters by enabled/disabled toolsets (platform presets hermes-cli, hermes-telegram, hermes-acp). check_fn False hides the tool from the model.

Dispatch: model -> run_agent loop -> handle_function_call -> intercepts -> pre_tool_call hook -> registry.dispatch -> JSON error wrap -> post hook.

Errors always JSON {error: ...}. Terminal backends: local, docker, ssh, singularity, modal, daytona, vercel_sandbox. DANGEROUS_PATTERNS approval in tools/approval.py.

Adding a builtin: tools/your_tool.py + name in _HERMES_CORE_TOOLS. Prefer plugins for personal tools.

## Compare vs OpenClaw

OpenClaw uses tool groups (group:runtime, group:fs) and sandbox tool policy. Hermes uses named toolsets plus check_fn.
