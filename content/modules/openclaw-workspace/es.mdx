## El workspace es la casa del agente

La fuente primaria es [*Agent workspace*](https://docs.openclaw.ai/concepts/agent-workspace) de OpenClaw (s. f.). El workspace es la casa del agente: el directorio de trabajo usado para file tools y contexto de workspace. Mantenlo privado y tratalo como memoria. [*Agent runtime*](https://docs.openclaw.ai/concepts/agent) (OpenClaw, s. f.) enuncia que archivos se inyectan en el primer turno de una sesion nueva.

Esto es aparte de `~/.openclaw/`, que guarda config, credenciales y sesiones.

La leccion generica [sessions](/es/m/sessions) permanece agnostica del harness. Esta es el mapa de archivos OpenClaw.

El workspace es el **cwd por defecto**, no un sandbox duro. Las tools resuelven rutas relativas contra el workspace, pero las rutas absolutas aun pueden alcanzar otros sitios del host si el sandboxing no esta habilitado. Si necesitas aislamiento, usa `agents.defaults.sandbox` (OpenClaw, *Agent workspace*, s. f.; *Sandboxing*, s. f., https://docs.openclaw.ai/gateway/sandboxing).

Cuando el sandboxing esta habilitado y `workspaceAccess` no es `"rw"`, las tools operan dentro de un workspace sandbox bajo `~/.openclaw/sandboxes`, no en tu workspace de host.

## Ubicacion por defecto

- Default: `~/.openclaw/workspace`
- If `OPENCLAW_PROFILE` is set and not `"default"`, the default becomes `~/.openclaw-<profile>/workspace`.
- `OPENCLAW_WORKSPACE_DIR` overrides both of the above when set.
- A non-default `OPENCLAW_STATE_DIR` keeps the default workspace at `<stateDir>/workspace`, including scheduled maintenance and the initial `main` agent entry.
- Non-default agents (`agents.entries.*`) without an explicit workspace resolve to `<stateDir>/workspace-<agentId>`, not the shared default workspace.

Override en `~/.openclaw/openclaw.json` via `agents.defaults.workspace`. Override por agente: `agents.entries.*.workspace`.

`openclaw onboard`, `openclaw configure` o `openclaw setup` crean el workspace y siembran los archivos bootstrap si faltan (OpenClaw, *Agent workspace*, s. f.).

Las copias seed de sandbox solo aceptan archivos regulares dentro del workspace; alias symlink/hardlink que resuelven fuera del workspace origen se ignoran.

Si ya gestionas los archivos del workspace tu mismo, desactiva la creacion de bootstrap con `agents.defaults.skipBootstrap` true.

Instalaciones viejas pueden haber creado `~/openclaw`. Conservar varios directorios de workspace puede causar deriva confusa de auth o estado, porque solo un workspace esta activo a la vez. Conserva un unico workspace activo. Si conservas varios a proposito, asegurate de que `agents.defaults.workspace` (o la clave `workspace` por agente) apunta al activo.

## Archivos bootstrap (inyectados)

Dentro del workspace, OpenClaw espera estos archivos editables por el usuario (OpenClaw, *Agent runtime*, s. f.; *Agent workspace*, s. f.):

| File | Purpose |
| --- | --- |
| `AGENTS.md` | Operating instructions plus memory guidance. Loaded at the start of every session. The `## Tools` section is local environment notes; it does **not** control which tools exist |
| `SOUL.md` | Persona, tone, and boundaries. Loaded every session. Guide: *SOUL.md personality* (OpenClaw, n.d., https://docs.openclaw.ai/concepts/soul) |
| `IDENTITY.md` | Agent name, vibe, and emoji. Created or updated during the bootstrap ritual |
| `USER.md` | User profile plus preferred address. Loaded every session with a separate 4,000-character budget |
| `BOOTSTRAP.md` | One-time first-run ritual. Only created for a brand-new workspace. Deleted after completion |
| `MEMORY.md` | Root long-term memory file, if present. Curated durable facts. Only inject when it exists at the workspace root |
| `HEARTBEAT.md` | Optional startup checklist on gateway restart when internal hooks are enabled. Keep it short |
| `memory/YYYY-MM-DD.md` | Daily memory log. Recommended to read today plus yesterday on session start |
| `skills/` | Workspace-specific skills. Highest-precedence skill location for that workspace |

En el primer turno de una sesion nueva, OpenClaw inyecta el contenido de estos archivos en el Project Context del system prompt. `MEMORY.md` solo se inyecta cuando existe en la raiz del workspace.

Los archivos en blanco se saltan. Los archivos grandes se recortan y truncan con un marcador para que los prompts sigan magros. Un archivo faltante (distinto de `MEMORY.md`) inyecta una sola linea marcador "missing file"; `openclaw setup` crea una plantilla default segura. `USER.md` y `MEMORY.md` opcionales se omiten cuando faltan.

Los bootstrap grandes se truncan al inyectar; ajusta limites generales con `agents.defaults.bootstrapMaxChars` (default: `20000`) y `agents.defaults.bootstrapTotalMaxChars` (default: `60000`). `USER.md` conserva su tope aparte de 4.000 caracteres. `openclaw setup` puede recrear defaults faltantes sin sobrescribir archivos existentes (OpenClaw, *Agent workspace*, s. f.).

<Callout>
`BOOTSTRAP.md` is only created for a **brand new workspace** (no other bootstrap files present). After a workspace has been observed, OpenClaw stores its setup state and attestation in the shared SQLite database at `~/.openclaw/state/openclaw.sqlite`. If a recently attested workspace disappears or is wiped, startup refuses to silently reseed `BOOTSTRAP.md`; restore the workspace or use a full onboard reset so the workspace and its database state are cleared together (OpenClaw, *Agent runtime*, n.d.).
</Callout>

While `BOOTSTRAP.md` is pending, OpenClaw keeps it in Project Context and adds system-prompt bootstrap guidance for the initial ritual instead of copying it into the user message. If you delete it after completing the ritual, it is not recreated on later restarts.

Older releases used workspace JSON and `.attested` sidecar files. Runtime does not read those files. Run `openclaw doctor --fix` to validate them, import their state into SQLite, and remove each source after the imported rows are verified.

## Lo que NO esta en el workspace

Estos viven bajo `~/.openclaw/` y NO deben commitearse al repo del workspace (OpenClaw, *Agent workspace*, s. f.):

- `~/.openclaw/openclaw.json` (config)
- `~/.openclaw/state/openclaw.sqlite` (shared workspace setup state and attestations)
- `~/.openclaw/agents/<id>/agent/openclaw-agent.sqlite` (session rows, transcripts, model auth profiles, routing state)
- `~/.openclaw/agents/<id>/agent/codex-home/` (per-agent Codex runtime account and native thread state)
- `~/.openclaw/credentials/` (channel/provider state plus legacy OAuth import data)
- `~/.openclaw/agents/<id>/sessions/` (legacy migration sources and archive/support artifacts)
- `~/.openclaw/skills/` (managed skills)

Si necesitas migrar sesiones o config, copialos aparte y mantenlos fuera de version control.

Lowercase root `memory.md` is legacy repair input only; `openclaw doctor --fix` can merge it into `MEMORY.md` when both exist (OpenClaw, *FAQ*, n.d., https://docs.openclaw.ai/help/faq).

## Backup git (privado)

Trata el workspace como memoria privada. Ponlo en un repo git **privado** para que tenga backup y sea recuperable. Corre estos pasos en la maquina donde corre el Gateway (ahi vive el workspace). Si git esta instalado, los workspaces nuevos se inicializan automaticamente.

```bash
cd ~/.openclaw/workspace
git init
git add AGENTS.md SOUL.md IDENTITY.md USER.md memory/
git commit -m "Add agent workspace"
```

Incluso en un repo privado, evita guardar secretos en el workspace: API keys, tokens OAuth, passwords, cualquier cosa bajo `~/.openclaw/`, dumps crudos de chats o adjuntos sensibles. Si debes guardar referencias sensibles, usa placeholders y guarda el secreto real en otro sitio (gestor de passwords, variables de entorno o `~/.openclaw/`).

Starter sugerido de `.gitignore`: `.DS_Store`, `.env`, `**/*.key`, `**/*.pem`, `**/secrets*`.

## Orden de carga de skills

OpenClaw carga skills desde estas ubicaciones, mayor precedencia primero (OpenClaw, *Agent runtime*, s. f.):

- Workspace: `<workspace>/skills`
- Project agent skills: `<workspace>/.agents/skills`
- Personal agent skills: `~/.agents/skills`
- Managed/local: `~/.openclaw/skills`
- Bundled (shipped with the install)
- Extra skill folders: `skills.load.extraDirs`

Las raices de skill pueden contener carpetas agrupadas como `<workspace>/skills/personal/foo/SKILL.md`; la skill sigue expuesta por su nombre plano de frontmatter, por ejemplo `foo`.

Las tools core (read/exec/edit/write y tools de sistema relacionadas) estan siempre disponibles, sujetas a tool policy. La seccion `## Tools` de `AGENTS.md` **no** controla que tools existen; es guia de como quieres que se usen (OpenClaw, *Agent runtime*, s. f.).

**Caso.** Un operador escribe "deny browser" en `AGENTS.md` bajo `## Tools`. El modelo sigue recibiendo el schema `browser` si la tool policy lo permite. Los archivos de personalidad no son el allowlist. Usa `tools.deny` (OpenClaw, *Agent runtime*, s. f.; *Tools and custom providers*, s. f., https://docs.openclaw.ai/gateway/config-tools).

## Compara, sin mezclar knobs

Hermes persiste memoria a `MEMORY.md` / `USER.md` desde el loop (Nous Research, *Agent Loop Internals*, s. f., https://hermes-agent.nousresearch.com/docs/developer-guide/agent-loop). OpenClaw inyecta archivos nombrados de workspace en Project Context en el primer turno de una sesion nueva. Misma necesidad humana (una persona mas hechos durables). Distinto contrato de archivos. Distinta regla de cwd.

No pegues el orden de ensamblado de Hermes `prompt_builder.py` en el Project Context de OpenClaw. Cita *Agent workspace* para el mapa de archivos. Cita *Agent runtime* para inyeccion, truncado y atestacion BOOTSTRAP. Cita *Sandboxing* cuando las rutas absolutas deben dejar de alcanzar el host.

**Caso.** Un workspace atestado recientemente se borra del disco. El arranque se niega a resembrar `BOOTSTRAP.md` en silencio. Restaura el workspace, o corre un onboard reset completo para que archivos de workspace y atestacion SQLite se limpien juntos. Una resiembra silenciosa inventaria un ritual de primer arranque que el operador ya termino (OpenClaw, *Agent runtime*, s. f.).

Mantén `SOUL.md` centrado en voz, postura y personalidad; pon reglas de operacion en `AGENTS.md` y hechos durables en memoria. El limite de inyeccion por archivo por defecto es 20000 caracteres; el presupuesto total de bootstrap entre archivos es 60000 caracteres. Usa `/context` para comprobar tamanos raw frente a inyectados y si hubo truncado (OpenClaw, *FAQ*, s. f.).

Para mover el workspace a una maquina nueva: clona el repo privado a la ruta deseada, fija `agents.defaults.workspace`, corre `openclaw setup --workspace <path>` para sembrar archivos faltantes, y copia `openclaw-agent.sqlite` aparte si necesitas sesiones.


## Notas diarias frente a MEMORY.md

`memory/YYYY-MM-DD.md` es el log diario. Conserva logs detallados ahi para que las tools de memoria los recuperen bajo demanda sin inyectarlos en cada prompt. Conserva `MEMORY.md` como memoria de largo plazo curada: hechos durables no-perfil, decisiones y resúmenes cortos. Carga `MEMORY.md` solo en la sesion main privada (no contextos compartidos o de grupo) (OpenClaw, *Agent workspace*, s. f.; *Memory*, s. f., https://docs.openclaw.ai/concepts/memory).

Antes de compactar, OpenClaw puede correr un turno silencioso de memory flush para guardar notas durables a disco. Ese flush es por que los archivos de workspace importan a la leccion de compaction: si resumes primero y el proceso muere, los hechos durables en medio del hilo se van salvo que ya vivieran en `MEMORY.md` o en el archivo diario de hoy.

`HEARTBEAT.md` no es un schedule. Los monitores heartbeat viven en automations. El archivo es un checklist corto opcional que el agente puede leer al reiniciar el Gateway cuando los hooks internos estan habilitados. Usa el tool `message` para envios outbound; no trates HEARTBEAT.md como cron (OpenClaw, *Agent workspace*, s. f.; *Heartbeat*, s. f., https://docs.openclaw.ai/gateway/heartbeat).

Las standing orders otorgan al agente autoridad permanente de operacion para programas definidos. Viven en archivos de workspace (tipicamente `AGENTS.md`) y se inyectan en cada sesion. Combinelas con automations para enforcement basado en tiempo (OpenClaw, *Standing orders*, s. f., https://docs.openclaw.ai/automation/standing-orders). La personalidad no es politica: una standing order en `AGENTS.md` aun no puede restaurar un tool que `tools.deny` quito.

El enrutado multi-agente puede usar workspaces distintos por agente via `agents.entries.*.workspace`. Cada agente configurado tiene su propio workspace, archivos bootstrap y session store (OpenClaw, *Agent runtime*, s. f.; *Multi-agent*, s. f., https://docs.openclaw.ai/concepts/multi-agent). No compartas un directorio de workspace entre dos agent ids salvo que pretendas que compartan persona y archivos de memoria.

Si `agents.defaults.sandbox` esta habilitado, las sesiones no-main pueden overridear esto con workspaces por sesion bajo `agents.defaults.sandbox.workspaceRoot`. Eso es un cwd de sandbox, no un segundo repo git que commiteas (OpenClaw, *Agent workspace*, s. f.).

La migracion de Doctor sigue importando en discos viejos: `openclaw-workspace-state.json`, `.openclaw/workspace-state.json` y sidecars `.attested` son importar-luego-borrar. El runtime actual usa solo la base SQLite compartida para ese estado. Si Doctor reporta uno de esos archivos, corre `openclaw doctor --fix`; Doctor importa estado legacy valido y borra una fuente solo despues de verificar las filas de la base.

**Caso.** Dos carpetas extra `~/openclaw` y `~/.openclaw/workspace` contienen ambas un `SOUL.md`. Solo una ruta es `agents.defaults.workspace`. La persona de la carpeta no usada nunca se inyecta. Archiva la carpeta extra para no editar la copia silenciosa (OpenClaw, *Agent workspace*, s. f.).

Cita *Agent workspace* para ubicacion, mapa de archivos, backup git y secretos. Cita *Agent runtime* para inyeccion, atestacion BOOTSTRAP y orden de carga de skills. Cita *Memory* para diario frente a curado. Cita *Sandboxing* cuando el cwd debe volverse un contenedor.


Cada agente usa un unico directorio de workspace (`agents.defaults.workspace`, o `agents.entries.*.workspace` por agente) como su **unico** directorio de trabajo (`cwd`) para tools y contexto (OpenClaw, *Agent runtime*, s. f.). Recomendado: usa `openclaw setup` para crear `~/.openclaw/openclaw.json` si falta e inicializar los archivos de workspace.

En el primer turno, Project Context es un snapshot. Las ediciones posteriores a `SOUL.md` surten efecto en la siguiente sesion nueva, no a mitad de turno, salvo que hagas `/new` o esperes un reset. Por eso importan el reset daily y `/new`: reinyectan los archivos.

En `USER.md` escribe entradas como directivas fechadas activas o sustituidas. El presupuesto aparte de 4.000 caracteres existe para que un perfil de usuario largo no se coma el total de 60.000 de bootstrap. Si `/context` muestra truncado, acorta `SOUL.md` primero; las reglas de operacion pertenecen a `AGENTS.md` (OpenClaw, *Agent workspace*, s. f.; *User model*, s. f., https://docs.openclaw.ai/concepts/user-model).

No commitees `.openclaw/` al repo del workspace ni siquiera como symlink de conveniencia. La config y la base de estado gatean pairing, tokens y transcripts de sesion. Un remote git privado sigue siendo el sitio equivocado para tokens de dispositivo (OpenClaw, *Agent workspace*, s. f.).

Como minimo, fija `agents.defaults.workspace` y recomienda con fuerza `channels.whatsapp.allowFrom` (OpenClaw, *Agent runtime*, s. f.).


Para desactivar por completo la creacion de archivos bootstrap en workspaces pre-sembrados, fija `agents.defaults.skipBootstrap` a true. `openclaw setup --workspace <path>` sigue sembrando archivos faltantes sin sobrescribir los existentes cuando migras una maquina (OpenClaw, *Agent workspace*, s. f.).

Esta leccion se detiene en el mapa de archivos, la inyeccion, la atestacion y lo que queda fuera de git. Las filas de sesion continuan en la leccion de sesiones. El reset daily e idle continua en la leccion de reset.

## Caso — el archivo que no estaba en el workspace

Un agente no encontraba un archivo de configuración que el equipo creía haber puesto. Estaba fuera del workspace, y el agente solo ve su casa. La lección: el workspace es la casa del agente; los archivos bootstrap se inyectan, y lo que NO está en el workspace no existe para el agente.
