## Particularidad — LlamaIndex tiene forma de recuperación

LlamaIndex codifica el bucle general como **datos entra, respuestas salen**. LlamaHub es un registro de loaders. Los componentes arman un RAG: load → split → embed → store → `VectorStoreIndex`. El índice pasa a retriever, query engine o chat engine. Envuelve el engine como `QueryEngineTool` y tienes RAG agéntico: el modelo *puede* recuperar.

Agentes en este stack: **function-calling** (si el LLM tiene esa API), **ReAct** (cualquier chat), o un workflow a medida. `AgentWorkflow` puede tener varios agentes con handoff. El estado es un `Context` — sin él, el agente no recuerda.

Los workflows (los de LlamaIndex) son grafos por eventos cuando el pipeline de retrieval tiene etapas. No empieces aquí si solo necesitabas un bucle.

## Caso — el retriever siempre encendido de LedgerQ

LedgerQ envolvía cada mensaje en `as_query_engine` y lo llamaba agente. “¿Cuánto es 3×4?” pegaba a Chroma, traía una factura al azar y contestaba con un proveedor. Necesitaban una calculadora y permiso para *no* recuperar. Convertir el engine en `QueryEngineTool` de un ReAct arregló la aritmética y dejó las facturas opcionales.
