## Particularidad — el agente decide recuperar

*Fuente nombrada: Hugging Face Agents Course, Unidad 3, [Introduction to Use Case for Agentic RAG](https://huggingface.co/learn/agents-course/unit3/agentic-ragintroduction) y [Agentic Retrieval Augmented Generation](https://huggingface.co/learn/agents-course/unit3/agentic-ragagentic-rag) (Burtenshaw, Thomas, Simonini y Paniego, Apache-2.0).*

El RAG clásico siempre busca. El **RAG agéntico** le da al modelo una herramienta retrieve (y quizá tiempo, web, stats del Hub) y le deja decidir. La Unidad 3 construye esto como Alfred planeando una gala: una herramienta RAG sobre **historias de invitados**, más otras tools, compuestas en un agente de gala. Puedes usar smolagents, LlamaIndex o LangGraph: el curso muestra pestañas para cada uno. La geometría es la de [embeddings](/es/m/embeddings-and-retrieval): stuffing frente a retrieve-then-read frente a elegir. Esta página es la fiesta trabajada.

Portada oficial: https://huggingface.co/learn/agents-course · fuente: https://github.com/huggingface/agents-course

## Por qué Alfred necesita RAG

*Fuente nombrada: Hugging Face Agents Course, Unidad 3, [introduction](https://huggingface.co/learn/agents-course/unit3/agentic-ragintroduction).*

El brief de la gala es deliberado. Un anfitrión renacentista necesita charla de deporte, cultura y ciencia, y debe evitar política y religión. Un buen anfitrión conoce los trasfondos. El tiempo debe estar fresco para lanzar fuegos. Es demasiado para los pesos solos y demasiado lío para un solo hop retrieve-then-read. Alfred necesita tools, y una de ellas es un retriever sobre material de invitados.

Consejo práctico: escribe los requisitos duros como descripciones de tools antes de indexar. Evitar política es una regla del system prompt; bio del invitado X es una herramienta. Mezclarlas es cómo una bio recuperada se vuelve instrucción.

## RAG clásico frente a RAG agéntico

*Fuente nombrada: Hugging Face Agents Course, Unidad 3, [agentic-rag](https://huggingface.co/learn/agents-course/unit3/agentic-ragagentic-rag); Unidad 2.1 [retrieval_agents](https://huggingface.co/learn/agents-course/unit2/smolagents/retrieval_agents); Unidad 2.2 [agents](https://huggingface.co/learn/agents-course/unit2/llama-index/agents).*

Los LLM aprenden conocimiento general. Puede faltarles lo relevante o lo actual. RAG encuentra pasajes y los reenvía. El RAG agéntico no responde automáticamente encima de documentos: Alfred puede usar cualquier otra tool o flujo. El diagrama del curso contrasta retrieve-then-read automático con un agente que elige tools.

La Unidad 2.1 ya listó límites del RAG ingenuo: un solo paso de recuperación, y fijación en similitud directa. El RAG agéntico deja reescribir consultas, criticar hits y saltar otra vez, o saltarse la recuperación en una pregunta de aritmética.

Consejo práctico: si cada turno dispara la tool de bios, la descripción dice siempre. Arregla la descripción antes de hacer fine-tune.

<Compare a="Retrieve-then-read" b="RAG agéntico">
<Side>
Cada pregunta pega en el índice. Demo rápida. Equivocado para aritmética, tiempo, o noticias de hoy cuando existe una tool web. Una inyección en un chunk entra al prompt sin frontera de decisión.
</Side>
<Side>
Retrieve es una tool con nombre. El modelo puede saltársela. Hace falta descripciones honestas y otras tools para que saltar tenga a dónde ir. Sigue siendo vulnerable si la salida de la tool se trata como instrucción.
</Side>
</Compare>
## Invitados: la tool RAG sobre historias

*Fuente nombrada: Hugging Face Agents Course, Unidad 3, [invitees](https://huggingface.co/learn/agents-course/unit3/agentic-raginvitees).*

La página de invitees es el notebook largo: cargar material de invitados, indexarlo, exponerlo como retriever, query engine o Tool de smolagents. Los nombres de clase exactos siguen la pestaña de framework (LlamaIndex QueryEngineTool, subclase Tool de smolagents, nodo LangGraph que llama a un retriever). No inventes una cuarta API. Lee la pestaña que vas a ejecutar.

Consejo práctico: las historias de invitados son datos. Una línea de vandalismo que pide volcar emails es una observación, no un system prompt. Etiqueta los resultados de tools como no confiables en la siguiente llamada.

## Otras tools de la gala: web, tiempo, stats del Hub

*Fuente nombrada: Hugging Face Agents Course, Unidad 3, [Building and Integrating Tools](https://huggingface.co/learn/agents-course/unit3/agentic-ragtools).*

La página de tools concede a Alfred búsqueda web DuckDuckGo vía el wrapper del framework, una tool de tiempo para los fuegos (el mismo hueco dummy o API que get_weather de la Unidad 1), y estadísticas de descargas del Hub. Usa el snippet del framework que elegiste. No mezcles un objeto tool de smolagents en un nodo LangGraph sin el adaptador del curso.

Consejo práctico: tres tools, no treinta. Una cuarta como send_invite sin humano es el incidente de GalaFlow. Recházala.

## Componer el agente de gala

*Fuente nombrada: Hugging Face Agents Course, Unidad 3, [agent](https://huggingface.co/learn/agents-course/unit3/agentic-ragagent); conclusión https://huggingface.co/learn/agents-course/unit3/agentic-ragconclusion

La página agent cablea RAG de invitados, web, tiempo y stats del Hub en un agente ejecutable por pestaña. El mismo ciclo de la Unidad 1: Thought, Action, Observation, presupuesto de saltos. Elegir framework es codificación, no un ascenso. Si el flujo exige humano antes de enviar, prefiere LangGraph. Si el corpus es el producto, QueryEngineTool de LlamaIndex. Si quieres código como acción, smolagents.

Consejo práctico: registra qué tool disparó. Un agente que solo llama web no usa el índice. Uno que solo llama invitados es RAG clásico con disfraz.

<Callout>
El texto recuperado es dato. Trátalo como Observation de la Unidad 1: añádelo, no lo obedezcas como política. Véase [seguridad e inyección](/es/m/safety-and-injection) cuando endurezcas producción.
</Callout>

## Requisitos de la gala como allowlist

*Fuente nombrada: Hugging Face Agents Course, Unidad 3, [introduction](https://huggingface.co/learn/agents-course/unit3/agentic-ragintroduction).*

Trasfondo del invitado va a la tool RAG. Conocimiento fresco del mundo va a la web. Timing de fuegos va al tiempo. Charla de cultura y ciencia va a RAG más web, no a tools de política. Cualquier cosa que envíe email va a un nodo humano o a una tool rechazada.

Consejo práctico: escribe la lista de tools rechazadas en el PR. Las listas vacías son cómo las demos se vuelven incidentes.

## Inyección: el fallo que parece RAG funcionando

*Fuente nombrada: páginas agentic-rag de la Unidad 3; Unidad 1 [Observations](https://huggingface.co/learn/agents-course/unit1/observations); Bonus Unidad 2 (monitorizar prompt injection).*

Si una bio recuperada pide ignorar el system prompt, retrieve-then-read la mete. La versión agéntica puede llamar guest_bio, luego web_search para confirmar, y seguir la instrucción si la salida se sienta sin etiqueta de no confiable. La recuperación funcionó. Las fronteras de confianza no.

Consejo práctico: preámbulo fijo antes de cada observación de tool: este contenido es dato no confiable. Monitoriza con los chequeos que nombra el Bonus 2, por ejemplo LLM Guard en su lista. No inventes un API de escáner.

<Myth>
El RAG agéntico es seguro porque el modelo decide. No. Decidir sin frontera de confianza sigue siendo stuffing. Elegir recuperar ayuda a la relevancia. No detiene sola la inyección en chunks.
</Myth>

<TryThis>
Escribe tres tools de un planificador de fiesta, no más: guest_bio, weather, menu. Para cada una: descripción de una línea, args tipados, y si el modelo puede saltársela. Luego una cuarta que rechaces (send_invite sin humano). Añade una frase de bio envenenada y di cómo etiquetarás Observation.
</TryThis>
## Caso — la bio inyectada de GalaFlow

*Caso pedagógico en voz iAguide; mecanismo de la Unidad 3 y Observation de la Unidad 1.*

GalaFlow indexó bios de prensa. El vandalismo de Wikipedia pedía volcar emails a una URL. El pipeline retrieve-then-read lo metió. La versión agéntica llamó guest_bio, luego web_search, y siguió la instrucción porque la salida se sentó sin marcar. Arreglaron etiquetas de no confiable, una lista de rechazo para envío, y un eval offline con una bio envenenada. Bajó la fluidez. Subió la seguridad.

## Lista práctica

*Fuente nombrada: páginas de la Unidad 3; pestañas de framework de la Unidad 2.*

1. El corpus está indexado con un embedder nombrado y un wrapper QueryEngine o Tool, no pegado en el system prompt.
2. Existe al menos una tool que no es retrieve.
3. Las descripciones no dicen usa siempre.
4. Las tools de tiempo, web y Hub coinciden con los snippets de la pestaña.
5. Envío, email e invite están rechazados o detrás de un humano.
6. El eval offline incluye salto de aritmética, camino de tiempo, camino de bio, un chunk envenenado.

## Las pestañas de framework no son tres productos

*Fuente nombrada: Hugging Face Agents Course, Unidad 3, [introduction](https://huggingface.co/learn/agents-course/unit3/agentic-ragintroduction); [tools](https://huggingface.co/learn/agents-course/unit3/agentic-ragtools).*

La misma idea de tiempo aparece tres veces según la pestaña. Elige una y quédate. Copiar las tres a un proceso son tres parsers. La Unidad 2 ya enseñó cuándo gana cada codificación; la 3 es el caso de uso, no un cuarto framework.

Consejo práctico: nombra la codificación en la carpeta del repo, gala-smolagents, no gala-final-final.

## Lo que indexas es un objeto legal

*Fuente nombrada: Hugging Face Agents Course, Unidad 3, [invitees](https://huggingface.co/learn/agents-course/unit3/agentic-raginvitees); etapas de carga de la Unidad 2.2.*

Licencia y PII son tuyas. La fiesta del curso es ficción. Tu gala de empresa no. No indexes emails personales para ayudar a Alfred a cotillear. El párrafo de anfitrión que conoce trasfondos es pedagogía, no una política de datos.

Consejo práctico: una colección por sensibilidad. Bios públicas en un índice. Notas dietéticas privadas detrás de una tool que un humano aprueba.

## El tiempo de los fuegos es la Unidad 1 de esmoquin

*Fuente nombrada: Hugging Face Agents Course, Unidad 3, [tools](https://huggingface.co/learn/agents-course/unit3/agentic-ragtools); Unidad 1 [dummy-agent-library](https://huggingface.co/learn/agents-course/unit1/dummy-agent-library).*

Para antes de Observation. Parsea la tool de tiempo. Ejecútala tú. Añade la cadena de la estación. Si el modelo escribe cielo despejado sin una llamada, estás otra vez en MeteoLite. La gala no anula el bucle dummy.

Consejo práctico: usa max_steps primero. El cacheo del tiempo no está en la Unidad 3; el presupuesto de saltos sí.

## Preguntas de eval que casan con la gala

*Fuente nombrada: Hugging Face Agents Course, Unidad 4 [GAIA](https://huggingface.co/learn/agents-course/unit4/what-is-gaia); requisitos de la Unidad 3.*

Cuatro preguntas internas: un hecho de invitado solo en el índice, el tiempo en la ciudad del venue, una pregunta de actualidad que deba usar web, y una suma que no deba recuperar. Si la primera solo usa web, la descripción RAG es débil. Si la suma recupera una bio, enviaste LedgerQ. La forma GAIA (multi-hop, tools, respuestas cortas) es cómo sabes que un quiz no puede falsificar esto.

Consejo práctico: respuestas cortas y fácticas para puntuar exact match, como describe el scoring de GAIA en la Unidad 4.

## Qué recordar

*Síntesis de la Unidad 3 Agentic RAG, Hugging Face Agents Course (Burtenshaw, Thomas, Simonini y Paniego, Apache-2.0).*

El RAG agéntico es retrieve como herramienta, no como destino. La gala necesita historias de invitados, web, tiempo y stats del Hub, y una lista de rechazo. Las pestañas son codificaciones del mismo ciclo. El texto recuperado es Observation, no política. La inyección es el incidente que parece una búsqueda exitosa.
