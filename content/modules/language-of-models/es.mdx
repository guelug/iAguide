## Los tokens no son palabras

Un <Term id="token">token</Term> es el átomo que el modelo ve. En inglés suele caer cerca de 0,7–1 palabra por token; el código y otros idiomas se desvían. No hace falta una constante precisa. Hace falta el hábito: **cuenta tokens, no caracteres**, cuando pienses en coste, contexto y velocidad.

El tokenizador forma parte del artefacto. Un GGUF o una carpeta de Hugging Face con el tokenizador equivocado es otro modelo, aunque los pesos te suenen.

<Callout>
Regla práctica, no ley: una página de prosa suele ser unos cientos de tokens; un volcado JSON o un stack trace gordo puede gastar miles sin parecer “largo”.
</Callout>

*Fuente nombrada: Hugging Face Agents Course, Unidad 1, [What are LLMs?](https://huggingface.co/learn/agents-course/unit1/what-are-llms) (Burtenshaw, Thomas, Simonini y Paniego, Apache-2.0).*

Llama 2, por ejemplo, trabaja con un vocabulario de unos 32 mil tokens, no con las seiscientas mil palabras del inglés. El recorte es por eficiencia: piezas que se combinan. «interest» más «ing» da «interesting». El modelo no ve diccionario; ve ids.

## El siguiente token, siempre

La <Term id="next-token">predicción del siguiente token</Term> es el trabajo: dada la secuencia, producir <Term id="logits">logits</Term> — una puntuación por ítem del vocabulario —, pasarlos a probabilidades y elegir.

Eso es toda la generación. Planes, herramientas, trazas de «razonamiento»: más tokens, más bucles, más entrenamiento. El modelo sigue emitiendo un token cada vez.

## Tres familias, un motor de agente

El curso de Hugging Face dibuja tres familias de transformer. Los agentes casi siempre se sientan en una.

**Encoder** (BERT y primos). Entra texto; sale una representación densa, un <Term id="embedding">embedding</Term>. Clasificar, buscar, extraer entidades. Tamaño típico: millones de parámetros. No escribe el siguiente turno de un chat. La similitud entre vectores es una puntuación, no una prueba.

**Decoder** (Llama, SmolLM2, Gemma, Mistral, clase GPT, DeepSeek). Genera tokens nuevos, uno a uno, para completar una secuencia. Miles de millones de parámetros. Chat, código, el cerebro de un agente.

**Seq2Seq** (T5, BART). Encoder más decoder. Traducir, resumir, parafrasear. El encoder comprime; el decoder escribe. Un agente de tools no vive aquí por defecto.

<Compare a="Encoder (BERT)" b="Decoder chat / instruct">
<Side>
Sale un vector. Sirve para buscar y clasificar. No emite «llama a get_weather». Un agente no se sienta aquí.
</Side>
<Side>
Sale el siguiente token. Con plantilla de chat e instrucciones, esos tokens pueden significar una tool. El arnés parsea. El motor sigue siendo next-token.
</Side>
</Compare>

Los nombres que el curso pone sobre la mesa — GPT-4, Llama 3, SmolLM2, Gemma, Mistral, DeepSeek-R1 — son decoders. El LLM de un agente es un decoder **chat / instruct**, no un BERT con un system prompt pegado.


Si eliges un encoder para un chatbot, el síntoma no es «se equivoca»: es que no hay generación autoregresiva que parsear. Si eliges un T5 y esperas ReAct, estás en el mapa equivocado. La pregunta de compra no es «¿es un LLM?». Es «¿emite el siguiente token de un chat con plantilla?».

## Tokens especiales: diversidad, no memorización

Cada familia abre y cierra turnos con tokens distintos. El más importante es el de fin de secuencia (EOS): la generación **para** cuando el modelo lo predice.

No memorices el zoo. Mira el tokenizer_config.json del repo. Ejemplos del curso, solo para ver que no se parecen:

- GPT-4: `<|endoftext|>`
- Llama 3: `<|eot_id|>`
- SmolLM2: `<|im_end|>`
- Gemma: `<end_of_turn>`

DeepSeek-R1 usa `<|end_of_sentence|>`. Otro más. El punto no es la tabla; es que un delimitador copiado de otra familia es un bug. Lo abrimos en [tokenización](/es/m/tokenization).

## Autoregresivo hasta el EOS

Un LLM es **autoregresivo**: la salida de un paso entra como entrada del siguiente. El bucle sigue hasta el EOS, o hasta un tope de tokens que pones tú.

Dentro de un paso: tokenizas, el modelo arma una representación de significado y posición, y puntúa todo el vocabulario. Luego eliges. El curso te deja jugar con SmolLM2 hasta que emite `<|im_end|>`. Esa es la parada. No un segundo cerebro que «ya ha terminado de pensar».

## Palancas de muestreo

- **<Term id="greedy">Greedy</Term>** (temperatura 0, o argmax): siempre la puntuación más alta. Repetible si el runtime es determinista.
- **<Term id="temperature">Temperatura</Term>**: baja afila la distribución; alta la aplana. Muy alta se vuelve balbuceo.
- **<Term id="top-p">Top-p</Term>**: quédate con el conjunto más pequeño cuya masa sume p, y muestrea.
- **<Term id="top-k">Top-k</Term>**: quédate con k tokens y muestrea.

El curso nombra también beam search: explorar varias secuencias candidatas. Un chat de agente casi nunca lo usa como default. Greedy o muestreo, y un EOS.

<Myth>
«Temperatura 0 significa que el modelo es veraz.» No. Significa que es menos aleatorio. Un token equivocado y seguro sigue equivocado.
</Myth>

## Prefill frente a decode

<VisualSlot caption="Izquierda: el prefill escribe un bloque de KV. Derecha: el decode añade un token cada vez." />

Dos fases, una petición:

1. **Prefill** — ingerir el prompt (casi siempre en paralelo). Construir la caché <Term id="kv-cache">KV</Term>. Suele ser pesado en cómputo.
2. **Decode** — emitir un token, añadir sus keys/values, repetir. Suele estar limitado por **ancho de banda de memoria**: recorres los pesos para muy poco trabajo nuevo.

Por eso un system prompt largo duele en el primer token, y una generación larga duele en tokens por segundo a medida que crece la caché. El curso habla de «un paso de decode». iAguide añade las dos facturas: prefill y decode no duelen igual.

<TryThis>
En cualquier UI local que muestre conteos (llama.cpp server, Ollama, LM Studio), manda la misma pregunta corta dos veces: sola, y detrás de un archivo grande. Mira tiempo hasta el primer token frente a tokens/segundo. Estás viendo prefill frente a decode, no «al modelo confundiéndose».
</TryThis>

## Atención y ventana

La atención decide qué tokens importan para predecir el siguiente. En «The capital of France is …» pesan «France» y «capital». El principio next-token no ha cambiado desde GPT-2; lo que ha crecido es la escala y la longitud que la atención puede cubrir.

La <Term id="context-window">ventana de contexto</Term> es cuántos tokens el modelo puede atender **ahora**: system prompt, herramientas, el hilo hasta aquí y lo que va a escribir. No es memoria a largo plazo. Cuando se llena, algo tiene que salir: compactas, recuperas o abres otro hilo.

Las ventanas grandes no son gratis. Cuestan memoria de caché KV y suelen frenar el <Term id="prefill">prefill</Term>.


Consejo práctico: la ventana se come system + tools + hilo + lo que vas a escribir. Un catálogo de veinte tools no es «más capaz». Es más prefill y menos sitio para la Observation que de verdad importa. Recorta el catálogo; no pidas una ventana mágica.



## El wording del prompt es el trabajo

El único oficio del modelo es mirar cada token de entrada y elegir el siguiente. Por eso **cómo escribes** la secuencia importa. El prompt no es magia; es el contexto que la atención va a ponderar. Una instrucción vaga produce una continuación vaga. Una lista de tools precisa produce llamadas parseables — o no, si el arnés no las espera.


Un prompt de agente no es un género distinto. Es el mismo next-token, con más ruido en la ventana: política de sistema, catálogo de tools, historial, a veces un skill. Cada párrafo extra es prefill extra. Si no cabe, no «recuerda peor»: atiende peor, o recortas.

Consejo práctico: si el system prompt nombra una función que el runtime no registra, el modelo escribirá la llamada y nadie la ejecutará. Eso es Alfred sin bucle, más abajo. El wording importa porque el arnés también lee.

## Cómo se usa, sin receta

El curso ofrece dos caminos: correr el modelo en local si hay hardware, o llamarlo por API (Inference en el Hub es el ejemplo que ellos usan en la dummy library). iAguide no receta un binario ni un precio. Lo que no cambia: el cerebro sigue prediciendo el siguiente token. Cambia quién factura el bucle y quién posee la caché KV.

Los agentes del curso — y Hermes o OpenClaw, más adelante — no sustituyen este motor. Lo llaman. Un turno de agente puede ser varias llamadas al modelo: una para la Action, otra después de la Observation. Cada una paga prefill y decode. El coste es un bucle de tokens, no un número en dólares que esta lección no va a inventar.

## Preentrenar, luego quizá ajustar

El preentrenamiento es predecir el siguiente token (o un objetivo enmascarado) sobre texto masivo. De ahí sale la estructura del idioma. Después, un **ajuste supervisado** puede enseñar conversación, uso de tools, clasificación o código. Un modelo base completa texto. Un instruct ha visto plantillas. Mezclarlos es el bug de [tokenización](/es/m/tokenization).

El curso te deja dos caminos de uso: local, si hay hardware, o una API (Inference en el Hub, u otra). Esta lección no receta un binario. El motor es el mismo.

## El LLM es el cerebro, no el agente

Interpretar instrucciones, guardar contexto en la ventana, bosquejar un plan, decidir una tool: todo eso son tokens. El LLM es el **cerebro** del agente. El agente es el cerebro **más** el bucle, las tools, la política y la persistencia. Sin arnés, HuggingChat hablando de una cafetera no es un mayordomo. Es un decoder.

<Callout>
El curso lo dice sin adorno: el LLM es el cerebro, no el agente. Si tu demo «planifica» y nadie ejecuta, tienes un chatbot con vocabulario de mayordomo. El bucle está en [el arnés](/es/m/the-harness) y en [agente dummy](/es/m/dummy-agent).
</Callout>

</TryThis>

## Determinismo

Greedy más un kernel determinista más un prompt fijo puede repetirse. El muestreo no. Algunos kernels de GPU no son estables bit a bit. Si necesitas repetir — eval, tests — fija semilla, temperatura 0, y aun así trata la deriva de GPU como posible.


## Qué recordar

Un decoder chat predice el siguiente token hasta un EOS que **no** tienes que memorizar. Encoder y seq2seq existen; el agente casi nunca vive ahí. Prefill construye la caché KV; decode la alarga un token cada vez. Temperatura 0 no es veracidad. El LLM es el cerebro. El agente es el cerebro más el arnés.

Esta lección reescribe la página [What are LLMs?](https://huggingface.co/learn/agents-course/unit1/what-are-llms) del Curso de Agentes de Hugging Face y guarda el vocabulario iAguide (tokens, KV, prefill/decode) para que la Unidad 1 no flote sin metal.

## Caso — Alfred sin bucle

**Caso.** Un estudiante cableó HuggingChat a una API de cafetera y lo llamó agente. El modelo escribía planes («ve a la cocina…») y nunca emitía un tool call: nada en el prompt nombraba una función y nada en el runtime la parseaba. Tenían motor. No tenían arnés. El bucle vive en [el arnés](/es/m/the-harness) y la codificación dummy en [agente dummy](/es/m/dummy-agent).


La tentación es añadir un system prompt más largo («eres un agente, llama tools»). Sigue siendo next-token. Sin registro, sin parseo, sin Observation añadida por ti, el modelo completará una receta de cocina o un JSON de mentira. El curso te pide el cerebro aquí y el while en la lección del bucle.

No hace falta GPU para verlo. Escribe en papel los tokens de salida que *tendrían* que ser la Action, y los que *tendrían* que ser la respuesta al usuario. Si no hay un hueco en el medio donde el runtime escribe «15 °C», no hay agente.



Consejo práctico: si tu demo «planifica» en prosa y nunca emite un nombre de función que el runtime conozca, no subas la temperatura. Sube el arnés.
