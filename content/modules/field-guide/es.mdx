## 1. Elige un modelo

- ¿Tiene que quedarse en local? Si sí, solo <Term id="open-weights">pesos abiertos</Term>.
- Lee la <Term id="model-card">ficha</Term>: licencia, contexto, plantilla de chat, dense frente a <Term id="moe">MoE</Term>, tipos de archivo.
- Elige instruct/chat salvo que estés completando un prefijo a propósito.
- Escribe cinco prompts de humo *antes* de descargar.

## 2. Estima memoria (regla práctica, luego mide)

- Tamaño de archivo ≈ memoria de pesos a esa cuantización. La KV va aparte y crece con el contexto.
- Prefiere un quant que **quepa en VRAM o memoria unificada al contexto que de verdad vas a enviar**.
- Mide la memoria residente a 4k de contexto y luego a tu objetivo. Cree eso, no un tuit.

## 3. Cuantiza (solo si hace falta)

- Servicio en llama.cpp / Ollama: empieza por <Term id="q4km">Q4_K_M</Term> salvo que el humo falle.
- Servidor GPU: sigue los docs actuales de vLLM para AWQ / GPTQ / FP8 — no conviertas a GGUF "porque eso usaba el portátil".
- Entrenamiento: <Term id="nf4">NF4</Term> es el 4 bits de QLoRA, no una etiqueta GGUF.

## 4. Ejecuta en local

```bash
# Solo la forma — lee --help
# llama-cli -m tu-Q4_K_M.gguf -c 8192 -ngl 99
# ollama run <nombre>
```

Confirma que se aplica la **plantilla de chat** (Modelfile de Ollama / flags de chat de llama.cpp). Una completion cruda de un instruct se ve "tonta" y el bug es tuyo.

## 5. LoRA mínimo (opcional)

Solo si el humo falla de un modo que *el dato puede arreglar* (un formato, una jerga, una política de rechazo que te pertenece). No para "ser más listo".

- 20 prompts de eval del paso 1.
- Un stack: Unsloth *o* Axolotl *o* torchtune / MLX — no los tres.
- Rango 8–16, una época, mira el eval. Exporta adapter o GGUF. Repite los cinco humos.

## 6. Arnés mínimo (pseudocódigo)

```
allow = {"search", "read_file"}  # permisos

def turn(thread, user_text):
    thread.messages.append({"role": "user", "content": user_text})
    while True:
        prefix = apply_template(profile, compact(thread), tools)
        out = model.generate(prefix)          # prefill + decode
        if out.tool_call:
            if out.tool_call.name not in allow:
                thread.messages.append(deny(out.tool_call))
                continue
            result = run(out.tool_call)       # tu código, no el modelo
            thread.messages.append(tool_msg(result))
            continue
        thread.messages.append({"role": "assistant", "content": out.text})
        return out.text
```

Ese es el bucle del módulo 02. El modelo es una línea. El resto es el producto.

## Nombra la capa, luego el dialecto

Cuando algo se rompe en producción, nombra primero la capa:

- **Modelo** (pesos, plantilla, quant).
- **Arnés** (bucle, tools, caché, inyección).
- **Metal** (VRAM, batching, factura).

Luego, si el arnés es una particularidad, nombra el dialecto (Hermes, OpenClaw, smolagents, LangGraph, LlamaIndex) — **después** de la capa, no en su lugar.

La Bonus 3 de Hugging Face (agente de combate Pokémon) es un caso trabajado: Showdown es metal+reglas; el LLM es el modelo; `choose_move` es el arnés. En [agentes en juegos](/es/m/game-agents).

## Prefill y decode, lo que cambia cuando te importa

Una vez que tienes el arnés funcionando, las dos fases se convierten en la palanca de optimización:

- **Prefill** — pagas en cada turno del system prompt cacheable. Invertir en prefijos estables es la palanca de coste más barata.
- **Decode** — pagas por la respuesta del modelo. Invertir en respuestas concisas es la palanca de latencia por turno.

Si tu eval o tu chat cuesta más de lo esperado, casi siempre es una de las dos. El dashboard del proveedor te dice cuál.

<Callout>
En un modelo MoE 48B-A3B, el prefill es barato por FLOPs (3B activos por token), pero la atención sobre la KV sigue siendo densa. Hacer el contexto más largo sigue siendo caro incluso en MoE — el ahorro de FLOPs del FFN no abarata la atención.
</Callout>

## Tres cosas que te ahorras si lees esto antes de comprar

1. **Un modelo "más grande"** cuando lo que necesitas es un contexto más corto o un eval mejor. El tamaño de modelo no compensa un system prompt inflado.
2. **Una librería de agentes** cuando lo que necesitas es un `while` con `runTool`. La librería es ceremonia hasta que demuestres que el bucle no basta.
3. **Un plugin de RAG** cuando lo que necesitas es una tool `retrieve(query)` con un índice simple. El RAG no es un producto; es una tool con un índice detrás.

Cada una de esas compras malgastadas cuesta semanas. La regla es: **nombre la capa, después el dialecto, después la herramienta**.

## Tres cosas que compras si lees esto antes de desplegar

1. **Un test unit del bucle** — allow/deny, validación de esquema, stop-and-parse, alternancia de mensajes. Sin GPU. Sub-milisegundo.
2. **Un eval de 20 filas tuyas** — en tu dominio, con claves exact-match, tools fijadas. Cinco filas son una corazonada; veinte son un eval.
3. **Una observación mínima** — `cache_hit`, `tokens_in/out`, `tools_called`, `duration_ms` por turno. Si falta una, depurar es adivinar.

Estos tres cuestan un día y ahorran un trimestre.

## Cuando el curso y la realidad divergen

Tres casos donde el mapa no encaja con el territorio:

- **Tu arnés es un producto legacy** — Hermes 1.x, OpenClaw 0.x. Las APIs han cambiado; los nombres siguen. Lee los docs del producto, no el curso.
- **Tu modelo es un preview** — sin MoE público, sin cuantización pública, sin tool_call estable. El curso aplica en general; los detalles los da la ficha del modelo.
- **Tu proveedor tiene un comportamiento idiosyncrático** — caché de prompt que cuenta por 256 tokens, KV caché que se descarta tras N generaciones, etc. Lee los docs del proveedor; el curso da los principios.

## Caso — capa equivocada, dialecto correcto

Una caída parecía "LangGraph está roto." El grafo estaba bien; la GPU hacía OOM en la KV. Reescribieron el grafo una semana. Nombrar **metal** el primer día habría comprado menos contexto, no otra librería.

## Caso — dialecto correcto, capa equivocada (otra vez)

Un equipo reportó "Hermes ignora las tools." Cambiaron a OpenClaw. El problema seguía. El perfil no listaba las tools; el runtime no parseaba tool_calls. Depuraban el dialecto. El arnés — esta página — estaba vacío.

## Lista práctica

1. Seis pasos: ficha → memoria → quant → motor → quizá LoRA → arnés con permisos.
2. Prefill cacheable (invierte en prefijo estable); decode por respuesta (invierte en concisión).
3. Tres compras que te ahorras: modelo más grande, librería de agentes, plugin de RAG.
4. Tres compras que te convienen: test unit del bucle, eval de 20 filas, observación mínima.
5. Nombra la capa, luego el dialecto, luego la herramienta.
6. Cuando se quede viejo, parch ea el esquema. Quédate con el bucle.
