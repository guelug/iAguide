## The scheduler lives in the Gateway

OpenClaw's [*Automations*](https://docs.openclaw.ai/automation/cron-jobs) (n.d.) is the primary source. Automations are OpenClaw's built-in scheduler. The scheduler persists jobs, wakes the agent at the right time, and can deliver output to a chat channel, a webhook, or nowhere.

Manage automations with the `openclaw automations` CLI; `openclaw cron` remains an alias for the same commands.

Automations run **inside the Gateway process**, not inside the model. The Gateway must be running for schedules to fire. Job definitions, runtime state, and run history persist in the shared SQLite state database, so restarts do not lose schedules. Every automation run creates a background task record (OpenClaw, *Automations*, n.d.).

The generic [cron](/en/m/cron) lesson, if present, stays harness-agnostic. This one is OpenClaw Gateway automations.

```bash
openclaw automations create "2027-02-01T16:00:00Z" --name "Reminder" --session main --system-event "Reminder: check the automations docs draft" --wake now --delete-after-run
openclaw automations list
openclaw automations runs --id <job-id>
```

## Schedule kinds and timezone

| Kind | CLI flag | Description |
| --- | --- | --- |
| `at` | `--at` | One-shot timestamp (ISO 8601 or relative like `20m`) |
| `every` | `--every` | Fixed interval (`10m`, `1h`, `1d`) |
| `cron` | `--cron` | 5-field or 6-field cron expression with optional `--tz` |
| `on-exit` | `--on-exit` | Fire once when a watched command exits |
| `stream` | `--stream-command` | Fire from batched lines of a supervised command |

Timestamps without a timezone are treated as **UTC**. Add `--tz America/New_York` to interpret an offset-less `--at` datetime, or to evaluate a cron expression, in that IANA timezone. Cron expressions without `--tz` use the **Gateway host timezone**. `--tz` is not valid with `--every` or `--on-exit` (OpenClaw, *Automations*, n.d.; *Timezone*, n.d., https://docs.openclaw.ai/concepts/timezone).

Day-of-month and day-of-week use **OR** logic (Vixie/croner). `0 9 15 * 1` fires on every 15th and every Monday. To require both, use croner's `+` day-of-week modifier or guard in the prompt.

Recurring top-of-hour expressions are automatically staggered by up to 5 minutes. Use `--exact` to force precise timing.

Heartbeat scratch `tasks:` is retired. Run `openclaw doctor --fix` to convert each entry into an ordinary main-session automation job. Heartbeat scratch is now monitor prose only (OpenClaw, *Automations*, n.d.; *Heartbeat*, n.d., https://docs.openclaw.ai/gateway/heartbeat).

## Session styles

| Style | `--session` | Best for |
| --- | --- | --- |
| Main | `main` | Reminders, system events |
| Isolated | `isolated` | Reports, background chores (`cron:<jobId>` keys) |
| Current | `current` | Context-aware recurring work bound to the creation conversation |
| Custom | `session:custom-id` | Workflows that build on history |

Agent-turn jobs default to the creating conversation when the create request carries session context. CLI/API callers without a session key fall back to `isolated`. System events and heartbeats still default to `main`; command and script payloads still default to `isolated`.

Internal automation turns do **not** extend daily or idle reset freshness; only visible user activity updates session freshness. Isolated jobs get a new transcript/session id per run and do not inherit ambient conversation context from an older automation row (OpenClaw, *Automations*, n.d.).

Isolated automation and hook agent turns are explicitly unattended. The final reply must be the deliverable. Return `NO_REPLY` when nothing needs doing.

<Callout>
Command payloads are an operator-admin Gateway automation surface, not an agent `tools.exec` call. Creating, updating, removing, or manually running automation jobs requires `operator.admin`. Agent exec policy does not govern command payloads (OpenClaw, *Automations*, n.d.).
</Callout>

## Payloads and delivery

Every job carries exactly one payload kind: system event (`--system-event`), agent message (`--message`), command (`--command` / `--command-argv`), or script (`--script`). One additional kind, `heartbeat`, is system-owned and cannot be created through the CLI.

Delivery modes: `announce` (fallback-deliver final text if the agent did not send), `webhook` (POST finished event payload), `none` (no runner fallback). Webhook delivery cannot combine with chat delivery flags.

Every outbound automation webhook uses the strict SSRF guard. Allow only the receiver you trust with `cron.webhookSsrfPolicy.allowedHostnames`. Leave the policy unset to keep strict behavior (OpenClaw, *Automations*, n.d.).

On hosts with multiple configured channels, isolated announce jobs must set `--channel` unless a provider-prefixed `--to` or a preserved session route selects the channel. DM pairing-store approvals are not fallback automation recipients.

`webhookToken` is sent as `Authorization: Bearer` on automation webhook POSTs. Webhook URLs must not include embedded username/password credentials.

Archiving a session disables every enabled automation job bound to that session. Restoring the session does not re-enable those jobs; use `openclaw automations enable <id>`.

**Case.** A morning brief uses `--session isolated --announce --channel slack --to "channel:C123"` with `--tz America/Los_Angeles`. Cron without `--tz` would have used the Gateway host timezone instead (OpenClaw, *Automations*, n.d.).

**Case.** An agent creates a command payload job. It fails. Command payloads require `operator.admin`. Use `--message` for agent-authored chores (OpenClaw, *Automations*, n.d.).

Hermes cron, when present, is a Hermes scheduler (Nous Research, *Agent Loop Internals*, n.d., https://hermes-agent.nousresearch.com/docs/developer-guide/agent-loop). OpenClaw automations are Gateway-owned sqlite jobs. Do not paste a crontab line into `session.reset`. Cite *Automations* for jobs. Cite *Heartbeat* for the monitor. Cite *Session management* for idle clocks that automations do not extend.

Disable automations with `cron.enabled: false` or `OPENCLAW_SKIP_CRON=1`. `cron.store` is retired; use CLI or Gateway API.

One-shot jobs auto-delete only when `completionStatus` is `succeeded`. A required-delivery failure keeps the job disabled for inspection. Recurring execution errors back off 30s, 60s, 5m, 15m, 60m. A time-based recurring job auto-disables after 10 consecutive execution failures.

Condition-trigger scripts and script payloads run unattended with the owning agent's full tool policy, including `exec`. Treat them as unattended code execution. Set `cron.triggers.enabled: false` for a hard stop.

Gateway HTTP hooks (`/hooks/wake`, `/hooks/agent`) need `hooks.enabled` and a dedicated hook token. Query-string tokens are rejected. Keep hook endpoints behind loopback, tailnet, or a trusted reverse proxy. Do not reuse gateway auth tokens as hook tokens. Putting a Gmail hook on `main` is a security decision; keep a dedicated reader agent with sandbox `all`, `workspaceAccess: "none"`, and a tight allowlist (OpenClaw, *Automations*, n.d.).

`/loop` in chat is an owner-only shortcut that creates a recurring agent-turn job bound to that conversation.

Model override `--model` is the job primary. If it is not allowed, the run fails with a validation error rather than silently falling back. Configured fallback chains still apply unless `--fallbacks ""` makes the run strict.

This lesson stops at Gateway-owned jobs, isolated versus main, announce versus webhook, sqlite persistence, and operator.admin for command payloads. Pairing is not a cron recipient. Compaction is not how isolated jobs stay small; they already start fresh.

Per-run wall-clock budget: --timeout-seconds when set. Otherwise isolated agent-turn jobs are bounded by the scheduler 60-minute watchdog before the underlying agent-turn timeout (agents.defaults.timeoutSeconds, default 48 hours). Command jobs default to 10 minutes. Script payloads default to 5 minutes.

On Gateway startup, overdue isolated agent-turn jobs are rescheduled instead of replayed immediately, keeping model bootstrap out of the channel-connect window.

Isolated runs best-effort close tracked browser tabs for their cron session on completion. Cleanup failures are ignored so the run result still wins.

Isolated runs with the narrow automation self-cleanup grant can read scheduler status and may remove only their own job.

When a job hits timeoutSeconds, the scheduler aborts and gives a short cleanup window. If it does not drain, Gateway-owned cleanup force-clears that run session ownership so queued chat work is not stuck.

Pacing: recurring jobs can set pacing.min and pacing.max. During an agent-turn run, a paced job can call automations with action next_check. Failed and skipped runs discard the proposal.

Stream schedules keep an operator-authored argv command running. mode line accepts every line. mode match accepts only matching lines. Command payloads are rejected for stream schedules because process ownership would be ambiguous.

Fast failures restart with error backoff. Five consecutive runs shorter than 60 seconds leave the job in an error state.

New jobs that can run tools always store an explicit tool policy. Jobs created by an agent are capped to the tools available to that creating turn. Jobs created by an authenticated operator without --tools store an unrestricted star policy.

Before an isolated run starts, OpenClaw checks reachable local endpoints for configured ollama and openai-completions providers on loopback or private network. A down endpoint records skipped rather than starting a model call. The result is cached for 5 minutes per endpoint.

Failure notifications use one scheduler-owned threshold and cooldown. Default coverage after 2 consecutive failures with a 1-hour cooldown when a route exists. A time-based recurring job auto-disables after 10 consecutive execution failures; enable clears the reason.

Automation jobs do not infer a reply language from channel or locale. Put the language rule in the scheduled message.

## Case — the job that fired in the wrong zone

A team configured a daily cron at 9:00 without a timezone. The job fired at 9:00 UTC, which was 11:00 in their zone. OpenClaw's scheduler lives in the Gateway and schedule kinds include timezone: without it, the briefing arrived two hours late.
