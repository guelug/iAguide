## Summaries are not a new session id

OpenClaw's [*Compaction*](https://docs.openclaw.ai/concepts/compaction) (n.d.) is the primary source. Every model has a context window. When a conversation approaches that limit, OpenClaw **compacts** older messages into a summary so the chat can continue.

1. Older conversation turns are summarized into a compact entry.
2. The summary is saved in the session transcript.
3. Recent messages are kept intact.

OpenClaw keeps assistant tool calls paired with their matching `toolResult` entries when it picks a compaction split point. If the point lands inside a tool block, OpenClaw moves the boundary so the pair stays together and the current unsummarized tail is preserved (OpenClaw, *Compaction*, n.d.).

The full conversation history stays on disk. Compaction only changes what the model sees on the next turn.

New configs default `agents.defaults.compaction.mode` to `"safeguard"` (stricter guardrails, summary quality audits). Set `mode: "default"` explicitly to opt out.

The generic [sessions](/en/m/sessions) lesson stays harness-agnostic. This one is OpenClaw safeguard compaction.

## Auto, manual, flush

Auto-compaction is on by default. It runs when the session nears the context limit, or when the model returns a context-overflow error (OpenClaw compacts and retries). Set `agents.defaults.compaction.enabled: false` to disable the embedded runtime's proactive threshold compaction. Preflight and overflow-recovery paths remain available, as does manual `/compact`.

You will see `embedded run auto-compaction start` / `complete` in Gateway logs, `Auto-compaction complete` in verbose mode, and `/status` showing a compaction count.

Before compacting, OpenClaw automatically reminds the agent to save important notes to memory files. This prevents context loss. A silent **memory flush** turn can store durable notes to disk. Set `agents.defaults.compaction.memoryFlush.model` when that housekeeping turn should use a local model. The memory-flush model override is exact and does not inherit the session fallback chain (OpenClaw, *Compaction*, n.d.; *Memory*, n.d., https://docs.openclaw.ai/concepts/memory).

```text
/compact Focus on the API design decisions
```

Manual compaction uses `agents.defaults.compaction.keepRecentTokens` (default: 20,000) as its cut-point budget and keeps that recent tail in rebuilt context.

Three verbs, three pages (OpenClaw, *Compaction*, n.d.; *Session management*, n.d., https://docs.openclaw.ai/concepts/session).

## Safeguard quality

With the built-in safeguard quality guard enabled, OpenClaw applies the final summary budget before validation. Required headings must remain in the retained generated body, while pending asks and exact identifiers must remain in the exact text that would be stored. Invalid output gets only the configured number of corrective attempts. If no finalized summary passes, compaction stops before writing a transcript entry, keeps the original history, and surfaces the existing recovery outcome (OpenClaw, *Compaction*, n.d.).

Identifier preservation defaults to `identifierPolicy: "strict"`. Override with `"off"` to disable.

Setting a custom `provider` automatically forces `mode: "safeguard"`. If the provider fails or returns empty, OpenClaw falls back to built-in LLM summarization. The built-in quality audit and its corrective retries apply only to built-in summarization.

## Model, bytes, successors

By default, compaction uses the agent's primary model. Set `agents.defaults.compaction.model` to delegate summarization (`provider/model-id` or a configured alias). When unset, compaction starts with the active session model. If summarization fails with a fallback-eligible provider error, OpenClaw retries through the session's existing model fallback chain. The fallback choice is temporary and is not written back to session state. An explicit compaction.model override remains exact and does not inherit that chain (OpenClaw, *Compaction*, n.d.).

When `agents.defaults.compaction.maxActiveTranscriptBytes` is set, OpenClaw triggers normal local compaction before a run if transcript history reaches that size. Set a positive byte count or size string such as `"20mb"`; `0` or unset disables the guard. It does not split raw bytes; it asks the normal compaction pipeline for a semantic summary. For Codex app-server sessions, the same threshold caps native rollout transcripts and oversized native threads restart fresh. The byte guard applies to the active SQLite transcript history. Legacy JSONL checkpoint artifacts are not the active compaction target.

A context engine may return an explicit compacted successor session identity. OpenClaw adopts that successor and records checkpoint metadata against it. The **built-in SQLite compactor keeps the current session identity** and does not create a second runtime transcript. OpenClaw no longer writes separate `.checkpoint.*.jsonl` copies for new compactions.

By default, compaction runs silently. Set `notifyUser` true to show brief status messages when compaction starts and completes, and to surface a degraded notice when a pre-compaction memory flush is exhausted but the reply still continues.

## Compaction versus pruning versus reset

| | Compaction | Pruning | Reset |
| --- | --- | --- | --- |
| What it does | Summarizes older conversation | Trims old tool results | Mints a new sessionId |
| Saved? | Yes, in session transcript | No, in-memory per request | New id; archives may remain |
| Scope | Entire conversation | Tool results only | Session identity |

Cite *Session pruning* (OpenClaw, n.d., https://docs.openclaw.ai/concepts/session-pruning) for tool-result trimming. Cite *Session management* for daily/idle reset.

**Case.** Context feels stale after auto-compact. Use `/compact Focus on <topic>` or enable memory flush so notes survive. Do not turn on daily reset because "the summary is lossy" unless you actually want a new id (OpenClaw, *Compaction*, n.d.).

**Case.** Compacting too often. The model window may be small, or tool outputs may be large. Try session pruning first (OpenClaw, *Compaction*, n.d.).

## Compare, without mixing knobs

Hermes compression creates a child session lineage; `/resume` picks a session up (Nous Research, *Agent Loop Internals*, n.d., https://hermes-agent.nousresearch.com/docs/developer-guide/agent-loop). OpenClaw built-in compaction keeps the current sqlite session identity. Do not paste Hermes `compression.protect_last_n` into `keepRecentTokens`. Cite *Compaction* for summaries. Cite *Session management* for reset.

OpenClaw matches dozens of provider overflow strings (`request_too_large`, `context length exceeded`, Bedrock token-count errors, Ollama context length exceeded, and more listed on the page). Do not invent a custom matcher; the runtime already maps those errors into compact-and-retry.

Plugins register a custom compaction provider via `registerCompactionProvider()`. Configure its id under `agents.defaults.compaction.provider`. Providers receive the same instructions and identifier-preservation policy. OpenClaw still preserves recent-turn and split-turn suffix context after provider output.

Hooks: `before_compaction` and `after_compaction` live on *Hooks* (OpenClaw, n.d., https://docs.openclaw.ai/automation/hooks).

Incognito threads skip automatic memory flush and do not create a transcript archive. Compacting an incognito thread is still in-memory. Cite *Session management*.

Advanced knobs (reserve tokens, custom context engines, OpenAI server-side compaction) live on *Session management deep dive* (OpenClaw, n.d., https://docs.openclaw.ai/reference/session-management-compaction). This lesson stays on safeguard, tool pairs, flush, and `/compact`.

The particularity: compaction changes what the model sees, not the sqlite row identity, unless a context engine returns a successor. Default mode is safeguard. Flush memory before you fold the tail.

This lesson stops at summarise, tool pairs, safeguard audits, memory flush, and the compaction/pruning/reset split. Cron isolated sessions start empty and do not inherit this as a way to keep a chore thread small; they are already fresh per run.

Overflow recovery is not optional entertainment. When the model returns a context-overflow error, OpenClaw compacts and retries. Disabling proactive threshold compaction does not disable that recovery path or manual compact.

Heartbeat and cron turns may grow the transcript. They still do not extend idle freshness. Compaction can still run on a session that looks idle. Those are independent clocks.

If no finalized safeguard summary passes, compaction stops before writing a transcript entry. The original history remains. That fail-closed audit is why new configs default to safeguard instead of default.

Tokenjuice is a plugin for compacting noisy exec and bash tool output. It is not this compaction pipeline. Cite Tools overview if the noise is tool output rather than conversation turns.

## Case — the summary that lost the context

An agent compacted mid-task and the summary did not mention the open file. The agent continued as if nothing happened and overwrote the wrong file. The lesson: summaries are not a session id; if the summary does not preserve critical state, the task breaks silently.
