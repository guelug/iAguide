## A tool is a typed function you run

The model never “has bash.” It emits a structured **tool_call**. Your harness:

1. Exposes **schemas** the model can see this turn.
2. Looks the name up in a **registry**.
3. Applies **policy** (allow/deny, approvals, sandbox).
4. Runs a **handler** (or routes to a **backend**: local terminal, Docker, SSH, browser CDP…).
5. Appends a tool-result message and continues the loop.

<Path>
<Easy>
The model never executes anything. It emits a request with a name and arguments; your code validates it, runs it, and returns the result to the loop. Five boxes: schema, registry, dispatch, policy, backend. If a tool misbehaves, check first whether the model even saw it (schema) and whether your code let it through (policy).
</Easy>
<Hard>
The full chain: the schema is what the model sees this turn; the registry maps name to handler; dispatch parses, validates types, and calls; policy decides whether the schema is even shown; the backend executes (local terminal, Docker, SSH, CDP). A failure in any of the five looks like a dumb model, but it is not.

The golden rule: if policy removes a tool, the model never sees its schema. That is the gate. Not a "please" in the system prompt. And if the registry lacks the name, nothing runs, even if the model asks.
</Hard>
</Path>

## Plugin vs builtin

- **Builtin** — ships in the core tree (`tools/*.py` self-register in Hermes; core tool groups in OpenClaw).
- **Plugin** — registers through a context API without forking core. Prefer plugins for personal/vendor tools.
- **Skill** — instructions + existing tools (`SKILL.md`), not a new callable, when a workflow is enough.

Hermes auto-discovers top-level `registry.register()` calls; shadowing a name from another toolset needs `override=True` plus operator consent. OpenClaw filters tools by profile, allow/deny, provider restrictions, sandbox tool policy, and plugin availability — if policy removes a tool, the model never sees its schema.

## Terminal / browser as backends

“Run a command” and “drive a page” are **backends behind tools**, not separate brains. Hermes terminal backends include local, Docker, SSH, Daytona, Modal, Singularity, Vercel Sandbox. OpenClaw `browser` can target sandbox, host, or a paired **node** that has Chrome — Gateway proxies; no public browser port required.
